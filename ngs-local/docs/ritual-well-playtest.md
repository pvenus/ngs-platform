# 굿상에 물 올리기: 독립 플레이테스트

로컬 NGS의 **비나리 → 퍼즐 설계 → 굿상에 물 올리기 · 테스트**에서 실행한다. 기존 맵, 프랍, 조립 및 퍼즐 데이터를 변경하지 않는다. 테스트 미술과 좌표는 데모 파일에 있고 별도 요청이나 저장이 필요하지 않다.

- **공용 런타임** (`puzzle-state-runtime.mjs`): 이벤트에 연결된 규칙을 고르고 조건과 효과를 검증한다. 유효한 변경을 한꺼번에 반영하며 실패하면 상태를 바꾸지 않는다. 프랍의 상태와 위치를 따로 저장한다. 연타 게이지는 입력 횟수와 경과 시간으로 값을 계산하는 순수 함수다.
- **설계 데이터**: 픽업, 게이지 성공, 드롭 이벤트와 필요 상태, 효과, 연결 포인트를 정의한다. 이름과 상태의 물리 위치 또는 프랍 이미지는 포함하지 않는다.
- **테스트 조립**: 선언한 포인트에 고유 인스턴스를 연결하고 무대에 배치한다. 제상과 우물의 상대 배치만 테스트이며 실제 5구역 굿터 맵에는 반영하지 않는다.
- **웹 표현**: 실제 게임에서는 상호작용 대상을 액터가 결정한다. 이 테스트에서는 프랍 클릭으로 액터의 선택을 대신한다. 우물을 선택하고 F를 누르면 우물 옆에 게이지가 뜬다(팝업 없음). 이동이나 거리 판정은 구현하지 않는다. 스페이스 연타, 취소, 상태별 이미지와 피드백은 웹 UI가 표현한다. 유니티는 이 게이지의 시각 표현에 의존하지 않는다. 이 릴리스에 유니티 어댑터나 본 제작용 조립 편집기는 포함하지 않는다.
- **완료**: 빈 그릇을 획득, 열린 우물에 드롭, 물그릇을 제상에 드롭. 순서를 엉뚱하게 시도해도 자산이 소모되지 않는다. 같은 상태로 시작하려면 처음부터 버튼을 사용한다.

## 조립·플레이에서 실행

맵과 퍼즐을 선택하고 퍼즐이 노출한 네 개의 포인트(제상·물그릇·우물 몸체·뚜껑)에 실제 게시 프랍을 연결한다. 제상과 우물의 구역과 위치를 정하며, 그릇은 제상에, 뚜껑은 우물에 붙는다. 초기 테스트에서는 별도 물그릇 대신 재받이를 대역으로 고를 수 있다. 그릇의 가득 참은 인벤토리 색과 상태 이름, 뚜껑의 열림은 뚜껑 아트 숨김으로 표현한다.

같은 맵 ID의 최신 게시 버전이 가리키는 정확한 배경과, 현재 목록에 있는 프랍 리비전을 읽어 플레이한다. 테스트와 게시본 플레이 모두 WASD로 이동하며 실제 맵의 포털을 이용한다. 복귀하려면 맵에 돌아오는 연결이 있어야 한다. 구역을 바꿔도 퍼즐과 인벤토리 상태가 유지된다. 조립 설정은 브라우저 세션에만 남으며 원본 맵·프랍이나 게임용 조립 데이터를 저장하지 않는다.


맵 전체의 구역 배경과 프랍 자리를 함께 표시한다. 한 맵에 여러 퍼즐을 추가할 수 있으며 각 추가 항목은 프랍이 선택되지 않은 프리셋에서 시작한다. 목록이나 맵의 프랍 자리를 누르면 해당 프리셋만 수정한다. 제상과 우물은 다른 구역으로 옮길 수 있고 물그릇과 뚜껑은 연결 부모와 같은 구역 안에서 위치를 조정한다. 테스트 플레이는 현재 선택한 퍼즐 한 개만 실행하며, 다른 퍼즐의 연결과 배치는 변경하지 않는다.

선택한 프리셋은 수정 창의 **퍼즐 삭제**에서 확인 후 삭제할 수 있다. 해당 테스트 배치와 연결만 세션에서 제거하며 게시된 맵, 프랍, 다른 퍼즐 배치에는 영향을 주지 않는다.

## 정식 조립과 런타임 경계

조립·플레이 목록의 +는 선택한 맵·퍼즐과 요청 사항을 `assembly.generate`로 접수한다. 실행 결과에는 생성 당시의 맵 기록(플레이는 항상 같은 맵 ID의 최신 게시본 사용), 역할별 실제 프랍의 ID/리비전/해시, 구역 좌표와 부착 오프셋이 들어간다. 드래그와 퍼즐 추가·삭제는 로컬 초안에만 반영되고, 변경 적용은 게시 리비전을 조건으로 `assembly.update`를 요청한다. 마지막 퍼즐을 빼는 것도 조립본 수정이며 원본 프랍과 맵은 지우지 않는다. 구역 확대 상태에서는 정확한 위치를 놓고 전체 보기에서는 구역 간 이동을 수행한다.

- 프랍 정의는 표현에 사용할 자산과 앞으로 제공할 상태/부착 자리의 계약을 소유한다. 현재 시범 타입에서만 상태 이름과 그릇 자리의 역할을 정적 정의로 제공한다. 기존 프랍 패키지에는 상호작용 정보가 있지만 프랍별 상태/자리 저작 편집기는 이 릴리스에 없다.
- 맵은 배경·구역·이동 경로를 소유한다. 게시된 맵 수정은 기존 조립본에도 자동 반영되며 조립 배치나 프랍을 재작성하지 않는다. 퍼즐의 왕복 동선이 불가능하면 정식 저장을 막는다. 테스트와 게시본 플레이는 맵의 실제 나가는 연결만 사용한다.
- 퍼즐 모듈은 입력과 조건, 변경만 소유한다. 조립은 정적 배치와 버전 참조만 소유하고, 플레이는 인스턴스 상태를 정적 메타에 쓰지 않는다.
- 앞으로 스토리 연출은 `ngs:prop-changed`로부터 인스턴스 역할, 구역, 이전/이후 상태 및 자리를 관찰할 수 있다. 예: 같은 퍼즐 인스턴스의 그릇이 `filled`이며 `altar-socket`에 들어온 변화. 우물 게이지나 퍼즐의 내부 단계를 읽을 필요가 없다. 독립 완료 신호 `ngs:puzzle-completed`도 노출한다. 스토리 페이즈·NPC·대사·시네마틱 연결 편집기는 이 릴리스의 범위가 아니다.


정식 생성 v2는 맵 하나를 바탕으로 퍼즐을 최대 여덟 개 선택하며, 통합 요청 사항과 각 퍼즐 요청 사항을 별도로 문서 워커에 보낸다. CLI가 각 퍼즐 ID로 배치 좌표를 반환해야 하며, 빠진 퍼즐이나 도달할 수 없는 구역은 게시하지 않는다. 스토리·연출 연결은 별도 탭으로 노출하되, 그 탭의 메타가 도입되기 전에는 퍼즐 메타에 스토리 필드를 넣지 않는다.

로컬 플레이는 기존 프랍 조회 권한을 사용하며, 현재 게시 프랍과 조립본의 리비전·해시가 모두 같은지 확인한다. 다른 리비전을 조용히 대신 표시하지 않는다.

프랍 크기 100%는 게시된 **배치용 픽셀 PNG의 픽셀 수**를 맵의 실제 배경 픽셀 수로 나눈 기준이다. 예를 들어 폭 307px 프랍을 폭 1536px 배경에 놓으면 100%에서 배경 폭의 약 20%다. 확대는 배치를 바꾸지 않는다. 제상·그릇·우물·뚜껑 크기는 각각 10–300%로 조절하고 정식 수정 요청으로 저장한다. 기존 조립본은 100%로 열린다.

테스트와 게시본 플레이 모두 시작 지점에 액터를 표시한다. 한글 입력 상태에서도 WASD는 물리 키 기준이다. 입력 창으로 포커스를 옮겼다면 맵을 다시 클릭해 이동을 재개할 수 있다. WASD 두 키를 함께 누르면 대각선으로 이동하며, 맵에 지정된 포털의 영역과 도착 좌표, 충돌 도형을 사용한다. 프랍과 가까울 때만 F 및 그릇 드롭을 받는다. 이 액터는 웹 플레이 검증용 위치 마커이며 애니메이션이 달린 NPC 리소스는 아니다.
