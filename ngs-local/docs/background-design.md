# 비나리 배경 설계
로컬 배경 설계 → + 버튼은 원본과 픽셀 보정본을 만드는 정식 요청 1건을 접수한다. 제목과 시간대·계절·분위기·주조색·장소·필수 요청 사항이 필수이며, 추가 요청 사항은 선택이다.
기존 프랍 및 시네마틱과 동일한 UI 컴포넌트를 사용하되, 배경 목록 및 원본은 별도로 관리한다.

`background.source.generate` → `background_source_generate` (기존 이미지 워커 1회) → PDS를 통해 Filex 원본 게시 → 로컬/Space 사본 조회.
기존 시네마틱 원본 및 프랍 작업에는 영향을 주지 않는다. 이 흐름은 별도 애니메이션이나 배경 제거를 생성하지 않는다.
두 마스터 컨셉은 작업을 인수한 워커가 현재 Filex 원본에서 읽는다. 공용 디자인은 시각 스타일과 표현 금지 규칙, 배경 디자인 설계는 공간 구성과 카메라, 동선에 적용한다.


## 배경 원본 + 픽셀 제작

로컬 배경 설계의 **+**은 큐에 `background.pixel.workflow` 1건만 넣는다. Planner의 시네마틱풍 순수 배경 원본 → 원본 PNG를 실제 이미지 레퍼런스로 붙인 픽셀 생성 → 기존 CPU 팔레트 보정 순으로 진행한다. 마지막 단계는 1536×1024 전체에서 좌표를 보존하며 거쳐간 픽셀의 색만 조정한다. 크기 축소, 재확대, 크롭, 배경 제거는 하지 않는다. 공용 표현/캐릭터·프랍 워커는 그대로이다. 픽셀 생성본은 후처리가 읽는 내부 산출물이다. 배경 목록에는 한 항목, 원본 이미지 탭에는 시네마틱 스타일 원본과 최종 픽셀 보정본만 표시한다. 로컬 화면에서는 기존 원본 단독 생성 버튼을 표시하지 않으나 과거 요청과 산출물은 그대로 보존한다. Space는 이번 변경의 배포 범위에 포함되지 않는다.

## 배경 애니메이션

애니메이션 탭에서 시네마틱 스타일 원본, 픽셀 보정본 중 하나 또는 둘 다 선택하고 연출을 한 번 입력한다. `background.animation.workflow` 한 건에서 선택한 이미지 해시를 각각 고정한다. 두 작업은 같은 연출과 메타를 사용하며 서로 기다리지 않는다. 현재 Mac의 단일 애니메이션 모델은 한 번에 한 작업을 렌더링한다. 결과는 24fps PNG 시퀀스로 게시되어 같은 요청 행에서 같은 재생·일시정지·구간 이동 컨트롤로 나란히 비교한다. 기존 단일 원본에는 유효한 레퍼런스 하나만 표시한다.

원본 이미지 카드를 누르면 실제 게시 PNG를 큰 팝업에서 본다. 애니메이션 요청 행의 버전별 확대 버튼은 각각 PNG 시퀀스 플레이어를 연다. 재생 시간과 별개로 원본 프레임 번호를 직접 이동하거나 한 장씩 넘겨볼 수 있다. 나란히 재생하는 비교 기능은 계속 제공한다.

배경의 연출은 시작·정지 이벤트가 없는 환경 루프만 받는다. 정식 요청에 고정 카메라·연속 루프 지시와 고정 재생 메타를 넣는다. 45개 PNG를 1→45→2 순서로 왕복하고 끝 프레임을 중복시키지 않은 264틱(11초)을 반복한다. 이 정책 이전의 단발 테스트는 원본을 삭제하지 않고 배경 애니메이션 탭의 재생 목록에서 제외한다.
